# AI向け要件パッケージの読み方

このフォルダは公開用の紹介ページではなく、設計・実装AIが参照する内部要件です。GitHub Pagesで公開するディレクトリは `docs/` のみにしてください。この `requirements/` を公開ページへ含めないでください。

## 読む順番

1. `requirements.json` — 要件ID、優先度、状態を機械可読で定義した索引。
2. `project_requirements.md` — 条件、報酬、ミッション、運営、テストを含む詳細仕様。
3. `boss_schedule.json` — 日数ベースの初期ボス解禁予定。
4. `mission_candidates.json` — 126件のミッション候補。初期条件は調整可能な案であり、そのまま全件採用するわけではない。

## AIへの重要指示

- このパッケージだけで実装を開始しない。ユーザーが仕様確定を明示するまでは、仕様整理と矛盾検出に留める。
- `confirmed` はユーザーの方針として維持する。`draft` は確定仕様のように扱わない。`validation_required` は実際の対象DLL・ソース・実機試験で検証し、未確認APIを推測で使用しない。
- 参加者コマンド不要、SSC、匿名性、既存Discord連携を変更しない、報酬の重複／消失を防ぐ、ロック中のボス全経路阻止は重要要件。技術的に満たせない場合に黙って省略せず、実装前に阻害要因と代替案を明記する。
- 日付・ミッション数・条件・報酬は後から変わる前提。コードにハードコードせず設定値として設計する。
- 公開用 `docs/index.html` は体験の説明用。API、SQLite、内部IDなどの実装詳細は、利用者が理解する必要のある安全上の注意を除き、公開ページに持ち込まない。
- ボス日程・候補ミッションは初期候補であり、仕様更新に応じて `boss_schedule.json` と `mission_candidates.json` を同時に更新する。
